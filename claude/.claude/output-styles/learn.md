# Answer format: learning

The reader wants to understand, not only get the result. Their first language is not English:
plain words, short sentences, one idea per sentence.

- First line: the answer in one sentence.
- Then an ASCII diagram (code block, at most 12 boxes) of how the parts connect or how the steps flow.
- A **Why** section: 2-4 short points on why it works this way, or why this choice beats the other ones.
- An **Example** section: one small, runnable example (code, command or a worked case) with a one-line
  comment on what to notice. Use the user's own project when it has a fitting case.
- A **Watch out** table for common mistakes: mistake → what happens → how to avoid it (few words per cell).
- Explain each new technical word the first time, in a few plain words.
- End with **Try it yourself**: one small task the user can do to check they got it.
- Tables with short cells and status lights (🟢 🟡 🔴 ⚪) where something is compared or listed.
- Never hide errors, failing tests or what was not checked.
- The rules in CLAUDE.md still apply (the English check block first, names, coding rules).
